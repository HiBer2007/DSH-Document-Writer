# 人味评审规则（human-rubric）

> 给**独立评审子代理**用的评分依据。评审对象是降重后的 Markdown，不是成品 docx。
> 主代理不得自评；评审必须在**新上下文**里完成，只看文本与依据，不看写作过程。

---

## 0. 一句话

低 AI 率 ≠ 像人。旧办法用同义词替换把检测分压下去，结果写出了"翻译机味"。
本规则要求同时看三轴：**AI 率、AI 味、机器味**，任何一轴超标都不算过。

---

## 1. 三轴定义

### 轴 1：AI 率（detector risk）

> 说明：AI 率是**概率代理**，不是“AI 写了百分之几”。检测器在改写、跨模型、跨领域、
> 中文长句下都会误判；文献与机制见 [`ai-detection.md`](ai-detection.md)。
> 本轴只作风险提示，最终以三轴 + 独立评审 + 人工确认为准。

被主流检测器判为 AI 的概率代理值，0–1，越高越危险。

看这些信号：

| 信号 | 高风险表现 |
| --- | --- |
| 句长突发性 | 句长变异系数 CV < 0.35，句子长度整齐 |
| 段落对称 | 连续 3 段以上长度相近（偏差 < 20%） |
| 模板句式 | "综上所述""随着…的发展""在…的背景下""近年来" |
| 模糊归因 | "有研究表明""学界普遍认为""众所周知" 且无引用 |
| 空洞结论 | "具有广阔的应用前景""具有重要意义" |
| 结构痕迹 | 冒号并列、嵌套编号、每段三点式 |
| 被动密度 | 每句被动标记 > 0.3 |

**禁止用"降智"换分**：拆成碎句、故意加错别字、乱加口语词，都会让轴 3 爆表。

### 轴 2：AI 味（generation flavor）

生成模型特有的"正确但空"的味道，0–1。

十种模式（详见 `references/ai-patterns.md`）：

1. 重要性膨胀（删掉"重要/关键"意思不变）
2. 同义词轮换（同一概念三个名字）
3. 三板斧强迫症（总凑三点）
4. 系词回避（"作为…的代表"而不说"是"）
5. 模糊归因（"有研究表明"无引用）
6. 公式化挑战段（"尽管…但仍存在局限"）
7. 悬浮式分析（一句挂两个"从而/进而"）
8. 空洞结论（"具有良好前景"）
9. 破折号滥用（一段两个以上"——"）
10. 虚假范围（"从宏观到微观"）

**鱼八股信号（DeepSeek 系常见）**：结构固化（总—分—总 / 现状—问题—对策 / 三段式）、
正确的空话（赋能、抓手、闭环、底层逻辑、新篇章、答卷等大词）、排比三连、金句结尾、
过度解释。命中 ≥2 类 → `aiFlavor` 至少 0.4，必须 revise。
**词表只是线索，不许用同义词替换冒充改写。**

### 轴 3：机器味（translationese / machine flavor）

读起来像翻译软件或公文模板，0–1。

| 类别 | 表现 |
| --- | --- |
| 翻译腔 | "在…的背景下""对于…而言""作为…的一部分""对…进行…""被…所…" |
| 名词化 | "可操作性""有效性""进行了深入的分析" |
| 连接词机械 | 首先/其次/最后、综上所述、由此可见、与此同时、此外 |
| 句式单一 | 每句 20–30 字、主谓宾齐全、无短句无插入语 |
| 无细节 | 只有结论没有过程，没有数字/时间/地点/动作 |
| 语义空转 | 一句话说两遍、形容词堆叠、说了很多没信息 |
| 标点节奏 | 40 字不断句、分号并列三项以上、破折号连用 |

详见 `machine-flavor.md`。

## 2. 像人判定

| 条件 | 结论 |
| --- | --- |
| 三轴都 ≤ 阈值 | **pass** |
| 任一轴超标 | **revise**，必须给 issue |
| 为降 AI 率牺牲可读性（碎句、错别字、过度口语） | **reject** |
| 学术语体被改成口语/网络用语 | **reject** |

默认阈值：`aiRate ≤ 0.35`、`aiFlavor ≤ 0.30`、`machineFlavor ≤ 0.30`。

---

## 3. 评审方法

1. **先通读一遍**，标出"读起来别扭"的句子——机器味通常先于数据被感知。
2. 再逐段对照三轴清单，不要只数词。
3. 每条 issue 必须：引用原文（≤30 字）+ 指出轴 + 给出具体改法。
4. 不许写"整体感觉还行""可以再润色"这类空结论。
5. 只评文本，不猜作者意图，不要求补充不存在的事实。
6. 引用、数据、术语不动；发现事实错误单列，不算文风问题。

---

## 4. 输出

按 `SKILLS.md` §7 的 schema 输出 JSON，必须包含：

- `axes`：三轴分数与命中信号；
- `verdict`：pass / revise / reject；
- `issues[]`：每条带 `axis`、`location`、`quote`、`fix`；
- `reviewer`：必须是 `subagent`；
- `reviewId`：由 `docwrite review open` 生成，不许自造。

---

## 5. 反模式（评审者自己别犯）

| 错误 | 后果 |
| --- | --- |
| 只数模板词，不看句子 | 漏掉机器味 |
| 把学术语体当机器味 | 改出口语，人审不过 |
| 把短句当人味 | 全文碎句，读起来更假 |
| 用同义词替换冒充改写 | 机器味更重 |
| 给"整体不错"的结论 | 无法执行，等于没评 |
| 要求补充不存在的数据 | 逼出编造 |

---

## 6. 与阶段的关系

- 评审发生在 **S7 降重之后、S8 转换之前**，对象是 `draft_reduced.md`。
- 评审不过 → 回 S7 继续 edit，不进入 S8。
- 评审记录进 `human-review.json`，`verify` 会核对 reviewer 是否为子代理。
